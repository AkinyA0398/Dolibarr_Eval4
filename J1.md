# Cahier des charges — J1

## Activer le module PRODUITS

## NewAPP

### Backoffice
- Authentification via **code unique comme mot de passe** (pas de login), pré-rempli par défaut sur le formulaire.
- Protéger les pages du backoffice.
- Créer une page avec un bouton pour **réinitialiser les données**.
- Créer la page pour **importer les 3 fichiers** `import-data-série4`.

### Dashboard

**Affichage :**
- Montant total des factures par mois, avec le montant payé et le montant restant.
  - Au clic sur un mois : afficher la liste des factures avec le montant payé et le montant restant.
- Vente totale des produits, avec le détail par produit au clic.

**Configuration (SQLite) — remise selon le jour de règlement**

Exemple (le nombre de lignes est configurable, pas forcément 4) :

| Délai de règlement | Remise sur la facture |
|---|---|
| Maintenant | 30 % |
| Moins d'1 semaine (7 jours) | 15 % |
| Moins d'1 mois (30 jours) | 10 % |
| Plus d'1 mois | 0 % |

### Frontoffice
- Login client avec son nom (ex : `rakoto`), auto-inscription si le client n'existe pas encore dans la base.
- Afficher la liste des produits.
- Créer un système de panier (pas de gestion de stock).
- Valider le panier pour créer la facture correspondant au client.
- Le client choisit la date de règlement :
  - Maintenant
  - Dans X jours (le client saisit le nombre de jours)
- Page de paiement du client (s'inspirer de la page **"Saisie règlement"** de Dolibarr).

## ExistingApp

S'assurer que :
- Toutes les données importées sont visibles quelque part dans le backoffice de **DOLIBARR**.
- La modification des données a un impact sur la **NewAPP**.
